# Kubernetes

This guide covers deploying Vectora on Kubernetes using Helm or raw manifests.

:::note
Kubernetes is recommended for teams requiring high availability, horizontal scaling, or GitOps workflows. For most self-hosted deployments, Docker Compose is simpler.
:::

## Prerequisites

- Kubernetes 1.28+ cluster (EKS, GKE, AKS, k3s, or bare-metal)
- `kubectl` configured for your cluster
- Helm 3.14+
- An external PostgreSQL database (RDS, Cloud SQL, or managed Postgres)
- An S3-compatible storage bucket

## Helm install

```bash
helm repo add vectora https://charts.vectora.company
helm repo update

# Create namespace
kubectl create namespace vectora

# Create secret with env vars
kubectl create secret generic vectora-env \
  --namespace vectora \
  --from-env-file=.env

# Install
helm install vectora vectora/vectora \
  --namespace vectora \
  --set envFrom.secretRef=vectora-env \
  --set image.tag=1.0.0
```

## values.yaml reference

```yaml
# values.yaml
replicaCount: 2

image:
  repository: vectora/vectora
  tag: "1.0.0"
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 8000

ingress:
  enabled: true
  className: nginx
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
  hosts:
    - host: chat.your-company.com
      paths:
        - path: /
          pathType: Prefix
  tls:
    - secretName: vectora-tls
      hosts:
        - chat.your-company.com

resources:
  requests:
    cpu: "500m"
    memory: "512Mi"
  limits:
    cpu: "2"
    memory: "2Gi"

autoscaling:
  enabled: true
  minReplicas: 2
  maxReplicas: 10
  targetCPUUtilizationPercentage: 70

persistence:
  enabled: false  # Use S3 storage backend instead
```

## Raw manifests

### Deployment

```yaml
# deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: vectora
  namespace: vectora
spec:
  replicas: 2
  selector:
    matchLabels:
      app: vectora
  template:
    metadata:
      labels:
        app: vectora
    spec:
      containers:
        - name: vectora
          image: vectora/vectora:1.0.0
          ports:
            - containerPort: 8000
          envFrom:
            - secretRef:
                name: vectora-env
          resources:
            requests:
              cpu: "500m"
              memory: "512Mi"
          livenessProbe:
            httpGet:
              path: /health
              port: 8000
            initialDelaySeconds: 30
            periodSeconds: 10
          readinessProbe:
            httpGet:
              path: /ready
              port: 8000
            initialDelaySeconds: 10
            periodSeconds: 5
```

### Service + Ingress

```yaml
# service.yaml
apiVersion: v1
kind: Service
metadata:
  name: vectora
  namespace: vectora
spec:
  selector:
    app: vectora
  ports:
    - port: 80
      targetPort: 8000
```

```yaml
# ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: vectora
  namespace: vectora
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
spec:
  ingressClassName: nginx
  rules:
    - host: chat.your-company.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: vectora
                port:
                  number: 80
  tls:
    - hosts:
        - chat.your-company.com
      secretName: vectora-tls
```

## Managed PostgreSQL

Do not run PostgreSQL in the cluster for production. Use a managed service:

| Provider | Service |
|---|---|
| AWS | RDS PostgreSQL 16 |
| GCP | Cloud SQL for PostgreSQL |
| Azure | Azure Database for PostgreSQL |
| DigitalOcean | Managed Databases |

Set `DATABASE_URL` in your secret:

```
DATABASE_URL=postgresql://vectora:password@db-host:5432/vectora
```

## Scaling

Vectora is stateless (sessions stored in PostgreSQL). Scale horizontally without coordination:

```bash
kubectl scale deployment vectora --replicas=5 -n vectora
```

Or configure the HPA in `values.yaml` (`autoscaling.enabled: true`).

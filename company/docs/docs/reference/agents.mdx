# Agents Reference

Vectora uses a multi-agent architecture built on LangGraph. The orchestrator routes tasks to specialized agents based on intent detection. Each agent has a defined toolset and a specific role in the execution graph.

## Orchestrator

The orchestrator is the entry point for every user message. It:

1. Classifies the intent (code task, search, RAG, or general Q&A)
2. Decides whether to respond directly or delegate to a specialist agent
3. Can invoke multiple agents in parallel using `asyncio.gather`
4. Merges results into a coherent response

The orchestrator never executes tools directly — it delegates.

## Coder Agent

Handles all coding, filesystem, and terminal tasks.

**Tools available:**
- All `File & Filesystem` tools
- All `Terminal` tools
- All `Git` tools
- `rag_search` (to look up project context)

**Triggers:**
- "write a function that..."
- "refactor this file"
- "run the tests"
- "create a migration"

**Behavior:** The Coder Agent follows a plan-execute-verify loop. It reads relevant files before editing, runs tests after making changes (if a test command is configured), and reports the result with a diff summary.

## Search Agent

Handles web research and knowledge curation.

**Tools available:**
- `web_search`
- `fetch_url`, `fetch_url_raw`
- `rag_ingest` (to persist useful findings)
- `rag_search`

**Triggers:**
- "what is the latest version of..."
- "find documentation for..."
- "search for examples of..."

**Behavior:** The Search Agent performs iterative searches, following links and synthesizing results. Found information can be ingested into the knowledge base for future retrieval.

## RAG Subgraph

Not an independent agent — a sub-pipeline invoked by the orchestrator and Search Agent when the query requires retrieval from indexed documents.

**Pipeline:**
```
Query → Query Expansion (LLM generates N variants)
      → Hybrid Search (dense Cohere + sparse BM25 → RRF merge)
      → Reranker (Cohere rerank)
      → Score gate:
          ≥ 0.7  → inject into context
          0.4–0.7 → search_audit → inject
          < 0.4  → Web Fallback → search_audit → inject
      → LLM + context → Response + source citation
```

**Configuration:**
```toml title="config.toml"
[rag]
chunk_size = 512
chunk_overlap = 64
top_k = 10
rerank_top_k = 5
score_threshold = 0.4
web_fallback = true
```

## Deep Agents (Pro)

Deep Agents are long-running agents that can autonomously break a complex task into subtasks, spawn sub-agents, and coordinate across multiple files and services.

**How to create a Deep Agent:**

```bash
vectora agent create --name "code-reviewer" --goal "Review PRs for security issues"
```

Deep Agents persist their state across sessions. Use `vectora agent list` to manage them.

**Execution modes:**

| Mode | Description |
|------|-------------|
| `interactive` | Pauses for confirmation before destructive operations |
| `auto` | Runs fully autonomously, reports at the end |
| `scheduled` | Runs on a cron schedule |

## Parallel Execution

The orchestrator can run multiple agents in parallel when a task has independent subtasks:

```
User: "Refactor the auth module and document the REST API"
  → Coder Agent: refactor auth module (parallel)
  → Search Agent: find REST API docs format (parallel)
  → Orchestrator: merge results when both complete
```

Parallelism is transparent to the user — the response arrives after both complete.

## Customizing Agent Behavior

System prompts and agent parameters can be tuned per-workspace:

```toml title="config.toml"
[agents.coder]
system_prompt_append = "Always write type annotations. Prefer functional style."
max_iterations = 20

[agents.orchestrator]
temperature = 0.3
```

## Agent Logs

All agent steps are logged to `~/.vectora/logs/agent.jsonl`. Each entry contains:
- `timestamp`
- `agent` (orchestrator, coder, search, rag)
- `tool` (tool name if a tool was called)
- `input` / `output` (truncated to 2000 chars)
- `tokens_in` / `tokens_out`

Enable verbose logging:

```bash
vectora --log-level debug chat "your question"
```
